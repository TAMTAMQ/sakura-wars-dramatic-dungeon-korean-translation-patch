# 번역 자산 구성

이 디렉터리는 번역 자산을 검토 가능한 여러 파일로 유지하기 위한 골격이다. 실제 직렬화 형식과 필드명은 대상 프로젝트가 정하되, 파일의 역할은 다음과 같이 나눈다.

- 색인에는 지원 원본, 선언한 대상 범위, 모집단 근거와 조사 완료 여부, 조각의 상대 경로와 순서, 현재 검토 승인을 둔다.
- `segments/`는 장면이나 스크립트 구역처럼 함께 이해하고 검토해야 하는 의미 단위별로 나눈다.
- 빌드는 색인에 열거된 조각만 읽는다. 디렉터리 전체 탐색이나 첫 일치로 제품 입력을 고르지 않는다.

조각은 임의의 행 수나 배치 크기가 아니라 독립적인 변경 이유를 기준으로 나눈다. 다른 장면과 별개로 재추출·재번역·검토할 수 있는 범위는 분리하고, 문맥을 함께 봐야 하는 짧은 대화까지 한 줄씩 흩뜨리지 않는다.

빌드 전에는 모든 조각을 합친 범위에서 안정 ID의 유일성, 보호 원문과 raw byte, 제어 토큰과 참조의 유효성을 확인한다. 단위별 검토 승인은 해당 안정 ID의 내용과 적용한 기준선에 묶으며, 변경되면 영향받은 단위만 다시 검토한다. 빌드 보고서는 색인과 사용한 조각을 각각 식별해 하나의 거대 파일로 합친 임시 산출물을 원천처럼 취급하지 않는다.

현재 알려진 모집단은 지원 원본에서 재현하는 추출 단계나 검토된 대상 명세에서 얻고, 그 ID가 번역 조각에 모두 존재하는지 비교한다. 번역 조각에 이미 들어 있는 ID를 다시 모집단으로 삼아서는 누락을 검출할 수 없다. 아직 번역하지 않은 단위는 지우지 않고 원문 유지 상태로 남긴다. 더 발견될 단위가 있다면 조사 중임을 명시하고, 릴리스 전에는 단위가 더 늘지 않는다는 근거로 선언 범위를 확정한다. 범위 확정은 게임 전체를 번역한다는 뜻이 아니라 메뉴, 본편 대사처럼 처음 선언한 대상의 경계가 정해졌다는 뜻이다.

## 번역 상태의 생명주기

각 의미 단위는 미번역, 작업 중, 교차 검토 필요, 사람 판단 필요, 완료 가운데 현재 상태를 표현할 수 있어야 한다. 프로젝트는 다른 이름이나 더 세분된 상태를 써도 되지만, 빌드에서 원문을 유지할지 현 번역을 사용할지의 선택과 번역 완성 상태를 하나의 값으로 합치지 않는다. 미완료 단위는 기본적으로 원문을 유지한다. 목적·범위·기준선을 밝힌 비배포 개발 입력 정책은 명시적으로 선택한 초안을 기술 실험에 사용할 수 있지만, 그 사용으로 검토 상태나 배포 적격이 바뀌지는 않는다.

상태는 필요에 따라 이전 단계로 돌아간다. 원문 범위, 제어코드, 용어, 글리프 공급이나 배치 조건이 바뀌면 영향을 받은 단위를 다시 검토 대상으로 돌린다. 각 단위는 안정 ID 하나로 추적하고 같은 단위의 상태를 갱신한다.

선언한 번역 범위의 사람 검수는 릴리스 후보 전에 완료한다. 글리프 공급, 렌더 경로와 배치가 바뀌면 결과가 무효화되는 검수는 먼저 그 기술 조건의 위험을 확인하되, 영향받는 범위만 미룬다. 의미·용어·말투·원문 해석처럼 기술 설계와 독립적인 판단은 근거가 안정되면 진행할 수 있다. 그전에도 미완료 단위를 원문으로 유지하며 개발 빌드와 기술 검증을 계속한다.

표시 확인에 실패하면 현재 설계나 구현에서 확인한 충돌로 기록한다. 그 사실만으로 번역을 결함으로 판정하거나 게임·플랫폼에서 표시가 불가능하다고 단정하지 않는다. 적용 가능한 사람 결정을 유지하면서 원인을 해결할 관련 설계·문안·범위 선택지를 필요한 만큼 비교한다.

릴리스 승인은 단위별 완료 상태와 별개다. 선언한 범위가 완료된 뒤 사람이 색인과 사용한 모든 조각의 내용 해시를 함께 승인한다. 번역 내용, 보호 정보, 알려진 ID 모집단이나 조사 완료 여부가 바뀌면 릴리스 승인은 무효가 된다. 단위별 문안·배치·표시 승인은 각 근거와 무효화 조건에 따라 영향받는 범위만 다시 판정하고, 영향받지 않은 승인은 유지한다.
