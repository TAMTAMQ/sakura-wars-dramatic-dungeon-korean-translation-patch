# 이미지·영상 번역 자산

`index.json`은 선행 중국어 패치가 실제로 바꾼 이미지 및 컷신 컨테이너 후보를
원본 NitroFS 경로와 해시로 고정한다. 중국어 결과 이미지는 제품 입력으로
복사하지 않으며, 일본어 원본을 추출한 뒤 한국어 대체 자산을 제작한다.

- `cinema/`, `icat/`, `lips/`: 이미지 추출→PNG 작업본→원래 팔레트/타일 형식
  재인코딩→동일 크기 또는 명시된 재배치 검증
  - NCGR+NCER 자산은 `*.cells.png` 연락 시트로 전체 모습을 확인하고,
    `*.cells/cell-NNN.png`의 투명 RGBA 프레임을 편집한다. NCER 좌표와 OAM
    1D 128K 타일 매핑은 변환기가 자동으로 적용한다.
  - LIPS는 중국어 패치가 수정한 7세트뿐 아니라, 한자 공용이라 중국어판에서
    그대로였던 `lips01_03_00`까지 포함해 한국어에 필요한 8세트를 관리한다.
- `cpk/faCpkData.cpk`: ITOC 내부 1,616개 항목을 분리했다. CLUT 이미지,
  NCGR/NCER 셀, 대기 영상의 원시 텍스처를 하나의 재조립 과정에서 합성한다.
  기존 번역이 더 오래된 정지 이미지 전용 재조립으로 사라지지 않도록
  `ImportCpkPng`도 `apply-cpk-text-images.py`를 사용한다.

## 편집 위치

- `work/visual-png`: 일본어 원본 확인본. 편집하지 않는다.
- `work/visual-png-prior-patch`: 중국어 패치 참고본. 편집하지 않는다.
- `assets/visual/edits/nitrofs`: 일반 이미지와 NCGR 셀의 한국어 편집본.
- `assets/visual/edits/cpk`: CPK 내부 이미지의 한국어 편집본.

`InitVisualEdit`은 일본어 원본 PNG에서 누락된 작업 파일만 복사한다. 이미 존재하는
한국어 편집본은 덮어쓰지 않는다. `ImportPng`과 `ImportCpkPng`은 위 편집 폴더만
읽어 바이너리 교체물을 만든다.

빌드는 색인에 명시된 `replacement_path`만 적용하며 `review_status`가 완료되지
않은 자산은 기본적으로 일본어 원본을 유지한다.

## 타이틀 대기 영상의 원시 텍스처

`cpk-raw-texture-translation.json`은 CLUT/NCGR 헤더가 없는 별도 텍스처를 관리한다.
기존 스캐너가 추출하지 못했던 `次回予告`와 분할 로고가 이 형식이다.

- `attract-preview.png`: 256×128, 4bpp. CPK 1539·1540·1542·1544의 4개 복사본.
  위쪽 256×104 영역의 원래 64픽셀 문자 칸 네 곳에 `차/회/예/고`를 배치한다.
  아래쪽 24픽셀 투명 영역은 원본 그대로다.
- `attract-logo.png`: 256×128, 8bpp. CPK 1539의 원시 로고 아틀라스.
  기존 한국어 로고의 글자를 본문·상단 문구·부제의 원래 영역에 배치한다.
  장식, 분할 좌표, 텍스처 크기, 팔레트와 애니메이션은 바꾸지 않는다.
- `startup-logo.png`: 이미 번역돼 있던 별도 시작 로고(CPK 1538)를 통합 재조립에도 포함한다.

채택 형식은 `tools/cpk_raw_textures.py`에 있다. 리소스 표의 주소는 하위 11비트가
0인 32바이트 정렬 주소 표현이고, 크기는 32바이트 단위다. 대상 원본의 강한 해시,
리소스·팔레트 순번과 영역을 검증하며, 등록한 편집 사각형 밖의 픽셀 변경은 거부한다.
주 빌드도 편집 PNG에서 계산한 텍스처를 최종 CPK에서 다시 읽어 대조하므로,
오래된 CPK를 새 이미지 대신 적용하면 실패한다.

검증 도구: `tools/verify-attract-textures.py`. 공개 v0.2와 비교해 CPK 밖 전체 ROM,
변경하지 않은 CPK 슬롯, 대상 아카이브의 다른 리소스와 팔레트 보존을 검사한다.


### 영상용 로고: 이미지 외곽 대신 실제 GPU 좌표로 분할

2026-10-26 보완: 알파 외곽이나 글자 모양으로 나눈 조각은 사용하지 않는다.
실행 중의 원본 GPU UV/화면 좌표를 읽어 고정 분할표로 채택했다.
본문은 6개 사각형, 상단 문구·부제는 각각 1개 사각형이다.
본문 UV에는 원래부터 2픽셀 중첩이 있으므로 새 글자를 외곽 기준으로 따로
줄이면 획과 기준선이 어긋난다.

`attract-master-body.png`, `attract-master-header.png`,
`attract-master-subtitle.png`는 모두 같은 **256×192 완성 화면 좌표계**를 사용한다.
`cpk-raw-texture-translation.json`의 `coordinate_cuts`가 각 원본 화면 사각형과
원본 UV 사각형을 고정한다. `tools/build-attract-logo.py`는 이 좌표로만 잘라
아틀라스에 넣는다. 이미지 경계 탐색·문자별 자동 분리·문자별 크기 조정은 없다.
원래 쿼드의 화면/UV 폭 차이만 원본과 같은 비율로 보존한다.

원본 UV (`left, top, right, bottom`):

- 본문: `[0,0,40,56]`, `[40,8,96,16]`, `[40,16,72,56]`,
  `[70,16,96,56]`, `[96,0,138,48]`, `[136,0,192,48]`
- 부제: `[0,80,105,96]`
- 상단 문구: `[0,56,96,72]`

채택 근거: `work/untranslated-audit/logo-redo/actual-logo-uv.json`.
이 파일은 렌더링된 3D 정점 버퍼에서 읽은 좌표이며, 원본과 동일한 코드·UV를
사용하는 검증 ROM에서 확인했다. 근거 캡처는 조사 결과이고 주 빌드 입력은
버전 관리된 고정 좌표표다.
