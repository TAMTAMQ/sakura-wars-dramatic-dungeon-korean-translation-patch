# 폰트 자산 구성

이 디렉터리는 채택한 글꼴 자산과 국소 교체 자산을 제품 입력으로 관리한다. 글꼴 원천은 기성 글꼴일 수도 있고 생성형 도구로 저작한 프로젝트 자산일 수도 있다. 대상 프로젝트는 승인된 시각 목표, 문자 범위, 실제 소비 경로, 비용과 배포 조건을 근거로 선택한다.

## 채택한 글꼴 자산

`sources/`에는 빌드가 직접 소비할 정확한 글꼴·글리프 자산이나, 사용자가 별도로 공급할 파일을 식별하는 프로젝트 입력을 둔다. 채택한 자산마다 다음을 확인한다.

- 안정된 식별자와 정확한 파일을 확인할 강한 해시
- 기성 글꼴이면 출처·버전과 사용·수정·재배포 조건
- 프로젝트에서 저작한 자산이면 선택한 결과의 정체성, 저작에 사용한 도구·참조, 권리 조건과 사람 승인 범위
- 공급하는 문자 범위와 적용할 렌더링 경로
- 결과 픽셀을 바꾸는 크기·기준선·이진화·여백 등의 변환 입력

생성형 제작은 후보 자산을 저작하는 과정이다. 사람이 정확한 글리프 집합과 적용 범위를 채택하면 그 결과를 고정된 제품 입력으로 관리한다. 비결정적인 창작 과정을 반복 빌드에서 다시 실행할 필요는 없으며, 새로 생성한 결과는 새 후보로서 영향받는 시각 결정과 증거를 다시 검토한다.

에이전트가 획 규칙, 도형 조합이나 임의의 픽셀 배치로 자형 자체를 발명하려 한다면 식별 가능한 기성 글꼴을 원천으로 삼고 그 절차를 결정적인 변환이나 보정으로 관리한다. 채택한 구성 글리프를 게임이 실행 중 조합하는 표현 방식은 자형 저작과 별개이며, 실제 소비 경로와 수명을 검증해 사용할 수 있다.

빌드는 명시적으로 선택한 자산만 읽는다. 디렉터리 자동 탐색이나 첫 일치로 글꼴을 고르지 않는다. 파일을 저장소에 배포할 수 없다면 식별 정보와 공급 조건을 추적하고, 사용자가 제공한 정확한 입력을 빌드에서 검증한다. 원천 메타데이터나 생성 기록만으로 현재 글리프가 그 결과임이 증명되지는 않으므로 실제 채택 파일의 정체성을 함께 기록한다.

문자 매핑의 형식과 위치는 프로젝트가 정한다. 다만 번역 인코딩과 글리프 변환이 함께 읽는 명시적인 제품 입력이어야 한다.

## 국소 교체

`overrides/`에는 기본 자산의 특정 글리프를 교체하는 채택 입력을 둔다. 각 교체에는 문자 또는 안정 ID, 적용 렌더링 경로, 교체 이유, 원천과 권리 조건, 사람 판단이 필요한 경우의 승인 범위를 연결한다. 전체 글꼴을 별도로 저작하기로 선택했다면 국소 교체로 가장하지 않고 `sources/`의 독립 자산으로 관리한다.

## 제품 빌드 연결

채택한 글꼴·교체·변환·문자 매핑은 검토 가능한 고정 빌드 입력으로 둔다. 대상 원본이나 다른 제품 입력에서 얻는 값은 같은 주 빌드에서 다시 만든다. 빌드는 생성형 저작을 다시 실행하지 않는다. 래스터화·크기 조절·보정·패킹 결과와 매핑 검증 보고서는 빌드 때 다시 만들며, PoC 출력이나 추적하지 않은 수동 변환 결과로 대체하지 않는다.

빌드 보고서는 실제로 사용한 자산과 교체 입력을 식별하고, 필요한 문자에 자산·교체·매핑이 없거나 글리프가 비어 있으면 결과를 만들지 않는다. 글리프 변환은 번역 인코딩과 같은 문자 매핑을 사용하며, 두 결과를 배치와 같은 최종 빌드에 합쳐 검증한다.
